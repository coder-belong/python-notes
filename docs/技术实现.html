python-notes 技术实现

「AI 应用开发笔记」网站：前端 Next.js 静态页面，后端 FastAPI，部署在 Vercel，线上地址 notes.belong.run。下面按「页面怎么出来 → 学习记录怎么记 → 怎么同步到账号 → 怎么部署」的顺序讲。

1. 整体结构

浏览器（前端）Next.js 静态页面
每秒记学习时长
存在 localStorage
登录后每 60 秒同步
⇄HTTPS
POST /sync
后端 APIFastAPI + SQLAlchemy
Vercel Serverless Functions
注册登录、同步、统计
⇄SQL
数据库线上：Neon（云 Postgres）
本地：SQLite 文件
backend/dev.db
  • 前端：笔记内容在构建时就转成了 HTML，线上是纯静态文件，打开就是成品，不需要服务器现做页面。
  • 后端：只管账号和学习记录，不参与显示笔记。不登录也能看笔记、记时长，只是记录只在本机。
  • 两者怎么通信：普通 HTTP 请求，浏览器主动发，后端应答。没有 WebSocket，也没有服务器推送。

4. 笔记怎么变成网页

所有笔记写在一个 Markdown 文件里，构建时一次性处理好：

content/notes.md
→
marked 解析成 token
→
按 # 阶段 分组、按 ## 节 切开
→
每节转 HTML，代码块用 highlight.js 上色
→
取出 ### 做右侧目录
→
next build 静态导出到 out/
  • Markdown 约定：第一个 # 是书名；# 阶段X：… 是分组；每个 ## 节 是一页；标题后面写固定 id，比如 ## 1.6 迭代器 {#iter-gen-deco}，学习记录按这个 id 存，改标题、改编号都不会丢。
  • 代码在 src/lib/notes.ts：loadNotes() 只在构建时运行（文件开头 import "server-only"），浏览器里拿到的已经是处理好的 HTML。
  • 单文件 HTML：npm run build 之后，scripts/single-html.mjs 把 CSS、JS 全部内联进 index.html，生成 dist/AI应用开发笔记.html，拷到哪里都能双击打开。

5. 页面切换：网址里的 #

整个网站只有一个页面，切换节靠网址里 # 后面的部分：

网址显示
notes.belong.run/首页：继续学习、热力图、目录卡片、学习路线
#llm-callid 为 llm-call 的那一节（4.1）
#progress学习过程页
  • 监听浏览器的 hashchange 事件，# 变了就换成对应的节。不用路由库，也不会刷新页面。
  • 每节记住各自的滚动位置，回来时滚到上次读到的地方。
  • 右侧「本节目录」点击时只滚动、不改 #，因为 # 被用来切换节了。
  • 节的 id 以前是按标题自动生成的，后来改成写死；legacy-ids.ts 里有一张「旧 id → 新 id」的表，打开页面时自动把老记录换成新 id。

6. 学习计时

src/lib/use-study.ts 每秒检查一次，三个条件都满足才加 1 秒：

  1. 页面在前台（没切到别的标签页）；
  2. 浏览器窗口有焦点；
  3. 最近 90 秒内有过滚动、鼠标、键盘或触摸操作。

加的这 1 秒同时记到三个地方：今天的总时长（热力图）、当前这一节的时长；这一节第一次学的话，再记下开始日期（学习过程页）。

频率做什么
每 1 秒判断在不在学，在学就在内存里加 1 秒
每 10 秒写一次 localStorage（切走、关闭页面时马上写）
每 60 秒登录了的话，把新增的部分同步到后端（见第 9 节）
「一天学满 10 分钟才点亮热力图、才算连续学习天数」的判断也在前端：STUDIED_DAY_SECONDS = 10 * 60。

7. 浏览器本地存储

都存在 localStorage，键名以 python-notes: 开头：

键内容
python-notes:study学习记录：每天秒数、每节秒数、学完了、番茄钟、开始和学完日期
python-notes:auth登录信息：token 和用户名
python-notes:sync同步状态：还没发出去的增量、发出去还没确认的那一批
python-notes:reading上次读到哪一节
python-notes:positions每节的滚动位置

学习记录长这样（前后端用的是同一个格式）：

{
  "days":      { "2026-11-23": 1820 },          // 日期 → 当天学了多少秒
  "sections":  { "llm-call": 640 },             // 节 id → 累计秒数
  "done":      { "llm-call": true },            // 节 id → 勾了「学完了」
  "pomodoros": { "2026-11-23": 2 },             // 日期 → 完成几个番茄钟
  "started":   { "llm-call": "2026-11-20" },    // 节 id → 第一次学的日期
  "finished":  { "llm-call": "2026-11-21" }     // 节 id → 学完的日期
}
localStorage 按网址分开：python-notes-one.vercel.app 和 notes.belong.run 各存各的。换域名后要在新网址重新登录一次，服务器上的记录会同步回来。

8. 注册和登录

POST /auth/login
用户名 + 密码
→
后端用 Argon2 校验密码哈希
→
签一个 JWT 返回
30 天有效
→
前端存进 localStorage
→
之后每个请求带
Authorization: Bearer …
  • 密码：只存 Argon2 哈希，不存明文（backend/app/security.py）。
  • token 放请求头，不用 Cookie：所以后端 CORS 可以写 allow_origins=["*"]，别的网站拿不到你的 token，开放也不会被冒用。单文件 HTML 用 file:// 打开时也能调接口。
  • token 失效：后端返回 401，前端自动退出登录，本机记录保留，下次登录接着传。
  • 密钥：签 token 用环境变量 JWT_SECRET；线上没配会直接启动失败，避免用默认密钥上线。

9. 学习记录同步

方式：定时发普通 HTTP 请求

浏览器
POST /sync　{ 新增的时长……, batch_id }　→
后端
按 batch_id 去重，把增量加进数据库
浏览器
←　返回账号的全部记录
后端
前端用返回值覆盖本地（再加上请求期间新增的）

什么时候发：登录后每 60 秒一次；切走、关闭页面时补发一次（fetch 带 keepalive，页面关了也能发出去）；刚登录、刚打开页面时发一次。

发「增量」不发「总数」

  • 发的是「今天又学了 60 秒、3.13 节又学了 60 秒」，后端用 INSERT … ON CONFLICT DO UPDATE 在原值上相加。
  • 两台电脑各学各的，加起来就是总时长，不会互相覆盖；数据库一条语句完成，两台同时同步也不会丢数据。

同一批不会算两次

  • 每批带一个随机 batch_id，后端处理过的记在 sync_batches 表里。网络断了前端重发同一批，后端发现处理过就不再加。
  • 前端把待同步的数据分成两份：pending（还没发）和 inflight（发出去还没收到回复）。没确认的那批下次用同一个 batch_id 重发。

第一次登录：本机原有记录并进账号

一台电脑第一次登录时，把本机已有的全部记录当成一批增量传上去，和账号里原有的加在一起（claimed 标记保证只传一次）。所以先当访客学、后注册，时长也不会丢。

为什么不用 WebSocket

  • 学习记录只由你自己的浏览器产生，没有需要后端实时推送的消息；另一台电脑的数据晚一分钟过来可以接受。
  • 后端跑在 Vercel 的 Serverless Functions 上，每个请求处理完就结束，不能维持 WebSocket 长连接。
  • 普通 HTTP 断网了下次重发就行，不用处理断线重连和心跳。

10. 后端接口

都在 backend/app/main.py，统一返回 { "code": 200, "msg": "ok", "data": … }，出错时 code 是 -1。

接口要登录作用
GET /否健康检查，返回服务名
POST /auth/register否注册，成功直接返回 token（等于已经登录）
POST /auth/login否登录，返回 token
GET /auth/me是查当前用户，前端用来判断 token 还有没有效、是不是管理员
POST /sync是上传增量、取回全部学习记录
POST /guest/sync否没登录的访客上报学习时长
GET /admin/users管理员所有用户的学习情况
GET /admin/guests管理员访客统计

注册、登录时如果带着访客 id，后端会记下「这个访客后来成了哪个用户」。

11. 数据库表

backend/app/models.py，启动时 create_all 自动建表（还没用 Alembic）。

表主键存什么对应前端字段
usersid用户名、密码哈希、注册时间—
study_daysuser_id + day每天学了多少秒、几个番茄钟days、pomodoros
section_statsuser_id + section_id每节学了多少秒、学完了没sections、done
section_datesuser_id + section_id每节开始学、学完的日期started、finished
sync_batchesuser_id + batch_id处理过的同步批次（去重用）—
guestsid访客 id、第一次和最近一次出现时间、后来成了哪个用户—
guest_daysguest_id + day访客每天学了多少秒—
  • 开始日期两台电脑都有时取早的；学完日期以最新发来的为准，取消「学完了」就清空。
  • section_dates 单独建表，而不是给 section_stats 加列：create_all 只会建新表，不会给已有的表加列。

12. 访客和管理员

  • 访客：没登录时前端随机生成一个访客 id 存在浏览器里，学习时长每分钟报给 /guest/sync。线上访客能免费看 10 分钟（GUEST_LIMIT），用完要注册或登录；本地开发不限时（GUEST_LIMIT_ON 只在非开发环境开）。
  • 管理员：用户名在环境变量 ADMIN_USERNAMES 里的就是管理员（默认 belong）。登录后在账号弹窗里多一个「所有用户的学习情况」，能看到每个用户和访客的时长。

域名是怎么接上的

浏览器查 notes.belong.run
→
腾讯云 DNSPod 回答：CNAME 到 dbcbc7509afe473c.vercel-dns-017.com
→
查到 Vercel 服务器的 IP
→
浏览器直接连 Vercel
→
Vercel 按域名找到 python-notes 项目
  • 腾讯云只负责「告诉浏览器去哪」，网页和接口的数据是浏览器和 Vercel 直接传，不经过腾讯云。
  • 原来的 *.vercel.app 在国内被 DNS 污染，查到的是假地址；换成自己的域名，查地址这一步走腾讯云，就绕开了。
  • HTTPS 证书由 Vercel 在检测到 DNS 生效后自动申请、自动续期。
  • belong.run 在 2026-12-27 到期，腾讯云开着自动续费，记得保证余额。

14. 本地开发

npm install
npm run dev

# 后端（http://localhost:8000），不配置也能跑：数据库用 backend/dev.db（SQLite）
